# Built modules

Part of the [Sprout architecture docs](README.md). See the [overview](1.%20overview.md) for goals and dependency direction.

| Module | Responsibility | Interface | Errors | Phase added |
|---|---|---|---|---|
| `config.py` | Env and `.env` into frozen `Settings` | `get_settings()`, `require_*_key()` | `MissingConfigError` | 1 |
| `models.py` | Taxonomy, `Sourced[T]`, `CompanyProfile` (`extra="forbid"`) | Pydantic classes | `ValidationError` for unsourced values, naive datetimes | 1 |
| `sources/http.py` | Single network entry point | `HttpClient.get`, `DiskCache`, rate limiters | `FetchError`; 4xx (not 429) no retry; 429/5xx retry 4 times with backoff; a response slower than `max_seconds` (30, 5) or over 5 MB fails without retry | 2 |
| `sources/companies_house.py` | Registry client | `search`, `advanced_search`, `get_company`, `filing_history`, `active_officer_count` (6, D34) | `FetchError` | 2 |
| `sources/rss.py` | Feeds to `NewsItem` | `fetch_feed`, `parse_feed`, `normalise_url` | One bad feed doesn't stop others | 2 |
| `sources/web.py` | Polite, safe page fetch | `WebFetcher.fetch`, `html_to_text`, `UrlPolicy`/`DEFAULT_POLICY` (5) | `FetchBlockedError` | 2 |
| `candidates.py` | Name and SIC heuristic; shell/non-AI pre-screen (6, D34) | `assess()`, `passes_prescreen()` | none | 2 |
| `db.py` | SQLModel tables and writes | `init_db` (create tables, then additive `ALTER TABLE` for missing nullable columns), `upsert_company`, `save_fact`, `add_news_items`, `logged_run`, `save_profile`, `save_funding_rounds`, `delete_profile`, `add_company_by_number`. Tables: `company`, `fact`, `funding_round` (3), `news_item`, `run_log`, `run_log_step` (4) | failures logged in `run_log` with a `failure_category`, re-raised; non-additive schema change raises `RuntimeError` telling you to reset the DB | 2 |
| `ingest.py` | Phase 2 orchestration | `python -m sprout.ingest` | exit code 1 on failed feeds | 2 |
| `app/queries.py` | Streamlit-free read queries | `search_companies`, `company_facts`, `company_funding_rounds`, `search_news`, `parse_phases`; Phase 4: `enrich_runs`, `failure_counts`, `cost_trend`, `daily_outcomes`, `run_steps` | none | Pre-7 (built ahead of schedule alongside the progress/test console); observability queries 4 |
| `costs.py` | Price table, `Usage`, USD cost (pure); per-run enrichment batch size (6, D34); shared batch USD cap (5, D24) | `PRICES`, `WEB_SEARCH_USD_EACH`, `Usage`, `cost_usd`, `enrichment_batch_size`, `BatchBudget` | `UnknownModelError` for an unpriced model (fails closed) | 3 |
| `agents/loop.py` | Generic tool-use loop; the only pipeline module importing `anthropic` | `run_agent`, `make_client`, `Budget`, `Tool`, `ToolOutcome`, `LoopResult`, `StepRecord` (4) | never raises for API, tool or model problems: returns a `LoopResult.stop` code; `ValueError` from `Budget` for bad caps; `UnknownModelError` before the first call | 3 |
| `agents/tools.py` | Tool specs, handlers, seen-URL ledger, untrusted wrapping | `build_tools`, `SourceLedger` (with `snapshot`), `wrap_untrusted`, `fetch_page_view`, `ALLOWED_ENRICHMENT_TOOLS` (5) | handlers return error outcomes, never raise into the loop | 3 |
| `agents/enrich.py` | Prompt, `submit_profile` schema and validation, persistence, `enrich` run_log row, CLI | `enrich_company`, `enrich_with_result` (both take `extra_context`), `validate_submission`, `submit_profile_schema`, `resolve_company`, `main` (`--max-total-usd`, default no cap) | `EnrichmentFailed(stop, cost_usd)` on any non-success; `RuntimeError` before the run if the tool set leaves `ALLOWED_ENRICHMENT_TOOLS`; `CompanyNotFound` for the CLI; exit 0 ok, 1 any skip or failure, 2 missing Anthropic key | 3 |
| `enrich.py` | `python -m sprout.enrich` shim | `main` re-export | see `agents/enrich.py` | 3 |
| `failures.py` | `FailureCategory` (8 values), `failure_category_for(stop)` (pure) | `FailureCategory`, `failure_category_for` | none | 4 |
| `app/dashboard.py` | Streamlit tabs (entry `streamlit_app.py`): Progress, Companies, News, Observability, Run & test (only with `SPROUT_ENABLE_ACTIONS=1`) | `render_*` functions over `app/queries.py` | empty and partial states render a message, never raise | Pre-7; Observability tab 4 |

Phase 5 (built) changed these modules in place (the `(5)` markers above): `sources/web.py` (`UrlPolicy`), `sources/http.py` (`max_seconds`), `agents/tools.py`, `agents/enrich.py` (`sources` in `stats`, tool-set check), `agents/loop.py` (notices name the terminal tool) and `costs.py`. `evals/` is new at the repo root, outside the package: `golden.py`, `metrics.py`, `judge.py`, `fixtures.py`, `injection.py`, `run_evals.py` (`python -m evals.run_evals`). See the [Phase 5 page](phases/phase-5-evals-guardrails.md).

Phase 3's built interfaces (exact signatures) and the loop contract table are on the [Phase 3 page](phases/phase-3-enrichment.md). Planned, not built, so not in the table: `agents/common.py`, `classify.py`, `news.py`, `verify.py`, `orchestrator.py` (with the `sprout/orchestrator.py` shim) and `status.py`, plus the in-place changes to `db.py`, `costs.py`, `loop.py`, `tools.py`, `enrich.py` and `sources/http.py`, all on the [Phase 6 page](phases/phase-6-multi-agent.md#changes-to-existing-code-planned). The [data model](2.%20data-model.md) (section 3.4) covers the SQLite schema these modules read and write.
