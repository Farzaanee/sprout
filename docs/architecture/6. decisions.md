# Key design decisions

Part of the [Sprout architecture docs](README.md). See the [overview](1.%20overview.md) and [cross-cutting concerns](4.%20cross-cutting.md) for the architecture these decisions apply to, and [risks](5.%20risks.md) for the open questions (A1-A32) many of them resolve.

| # | Phase | Decision | Why | Cost / rules out |
|---|---|---|---|---|
| D1 | 0 | Provenance enforced in `Sourced[T]` validator | Hallucinated funding is the top risk | A wrong but real URL still passes; verifier and evals catch it |
| D2 | 1 | SQLite single file, SQLModel, no migrations | Zero infrastructure, snapshot-friendly | One writer; manual reset on schema change |
| D3 | 1 | One HTTP entry point | Idempotent, polite, tested once | Sync and not thread-safe |
| D4 | 1 | Candidates by name and SIC heuristic | Free; no description search needed | Many shells; misses oddly named startups |
| D5 | 1 | Identity is the Companies House number | Numbers are stable | Other sources need a secondary dedupe key (website domain) |
| D6 | 2 | `category` is a plain enum, not `Sourced` | Classification, not a fact at a URL | No per-label provenance |
| D7 | 2 | Hand-written agent loop, no framework | Full control over the mechanics | Own the retries, caps and parsing |
| D8 | 2 | Server-side `web_search`; custom `fetch_page` (wraps `WebFetcher`) and `lookup_companies_house`; no server-side `web_fetch` | Keeps robots, SSRF, size and cache protections on every page read; no new key or adapter | Search is billed per query and returns unwrapped, encrypted snippets. Phase 7's MCP swap of `fetch_page` stays open (A2) |
| D9 | 2 | `costs.py` is a pure module (price table keyed by exact model ID, per-search price, `Usage`, `cost_usd`), written to `run_log.stats` on every run; caps are enforced in `loop.py`, not `costs.py` | Prices change with model IDs, so they are code that is tested and reviewed, not env | Unpriced model fails closed |
| D10 | 2 | Additive-column step in `init_db` instead of deleting the DB or adding Alembic now | Keeps ingest data and paid enrichment output | Cannot rename, retype or add constraints without a reset or Alembic; nullable columns only |
| D11 | 2 | Provenance is stamped by code: `retrieved_at` from the seen-URL ledger, `source_url` must be a URL a tool returned, funding facts need a `note` | The prompt cannot be the only defence against invented sources or timestamps | A real but wrong URL still passes; the verifier and evals cover that |
| D12 | 2 | `loop.py` is generic: terminal tools, handler callbacks, duck-typed client protocol; `enrich.py` owns the profile-specific checks | One loop can serve the classifier, news and verifier agents in Phase 5 | The generic `Tool`/`ToolOutcome` types are an abstraction paid for before a second user exists |
| D13 | 2 | `submit_profile` is not `strict`: the schema is derived from `CompanyProfile` and validated by Pydantic with one repair attempt | The API rejects the derived schema (29 anyOf/type-array parameters, limit 16) | Enforcement costs a possible repair round trip; numeric bounds and formats are Pydantic-only |
| D14 | 3 | Per-iteration steps go in a new child table `run_log_step` (one row per model response, FK to `run_log`, unique on `(run_log_id, iteration)`), not a JSON list in `run_log.stats` | Drill-down is one indexed lookup; steps stay queryable; matches how `fact` and `funding_round` were split out | A few more columns than a minimal design, because fresh `input_tokens` alone misrepresents the prompt under caching |
| D15 | 3 | `run_log.failure_category`, a nullable plain column filled from a fixed eight-value taxonomy in a pure `failures.py`; success is NULL; raw error and model text are drill-down only | Dashboard groups and filters with plain SQL or Python; one mapping reused by `enrich.py`, `logged_run` and the historical backfill | Taxonomy lives in code, not the database; `invalid` is not split by sub-reason (A8) |
| D16 | 3 | `run_agent` records `StepRecord`s on `LoopResult.steps` (and `error_type`); `enrich.py` persists them in the existing pre-raise commit; no callback and no DB import in `loop.py` | Cannot change loop behaviour; `loop.py` stays DB-free and the only `anthropic` importer; steps survive failed runs because stats already do | A hard process kill mid-run loses that run's steps; no live per-iteration progress until Phase 5 adds an `on_step` callback |
| D17 | 3 | Logged model text is untrusted: text blocks only, 1,000 characters plus a marker, verbatim, never prompted unwrapped, rendered only through `st.code`, `st.text` or dataframe cells | Bounds size and exposure; avoids Markdown image beacons from a poisoned page | Thinking blocks and tool inputs (for example the fetched URL) are not logged (A7) |
| D18 | 3 | Historical `enrich` rows get `failure_category` by an idempotent `init_db` backfill but no steps; the dashboard labels them "predates step logging" | Failure counts and cost trends cover all history; no invented data | The oldest runs cannot be drilled into |
| D19 | 4 | Evals live in a repo-root `evals/` package run with `python -m evals.run_evals`; it imports `sprout`, never the reverse | Keeps golden data and results beside the code but out of the shipped package | Two import roots; a new dev dependency for YAML (A20) |
| D20 | 4 | Evals run into `data/eval.db`, reset at the start of each full run, scored from the persisted `company`, `fact`, `funding_round` and `run_log` rows; `--score-only` rescores for free | Never touches the live dataset; evaluates the write path too | Seeding each company from Companies House; results depend on the cache state |
| D21 | 4 | "Fabricated" means the figure is absent from the cited page text as the model saw it, by number match within 1 percent; snippet-only sources are a separate "unverifiable" row | Exact and free; catches real-but-wrong URLs; the literal plan definition is always 0 percent since the code already rejects unsourced values | False flags for summed totals and spelled-out figures; cannot judge snippet-only claims |
| D22 | 4 | "Last round" is the `funding_round` with the latest `announced`, ties and missing dates by `Stage` order; a null amount still counts; match is exact or within 10 percent | Gives one unambiguous comparison; 10 percent absorbs approximate FX rates | A null amount on the latest round is a miss even if an earlier round is right |
| D23 | 4 | The judge is `run_agent` with a single terminal `submit_verdict` tool on the strong model, free-text fields only, three verdicts, calibrated against a hand-graded set | Reuses accounting, budget and the fake-client seam; judge differs from the generator | Added cost per run; a small calibration set gives a coarse signal |
| D24 | 4 | `BatchBudget` in `costs.py` (pure), shared by evals and the Phase 5 orchestrator | Closes the missing batch-level cap; one object caps every kind of spend in a run | Soft by one response; not thread-safe until the orchestrator adds a lock |
| D25 | 4 | `UrlPolicy` in `sources/web.py` (schemes, ports, name denylist, credentials, public-address rule with mapped-IPv6/NAT64 unwrapping, optional `allow_hosts` for fixtures) plus a `max_seconds` deadline in `HttpClient` | Closes known SSRF gaps on top of the existing per-hop checks | No production host allowlist, so any public host passes; DNS rebinding accepted |
| D26 | 4 | Injection tested in two tiers from one case list: offline `ScriptedClient` cases for code-level defences, and a live canary run for model behaviour; `ALLOWED_ENRICHMENT_TOOLS` is checked at runtime and in a test | A scripted model cannot show a real model resists | The live tier costs money and is non-deterministic; the suite covers only attacks already thought of |
| D27 | 5 | Deterministic orchestrator, not an LLM supervisor | Selection is rule-based | — |
| D28 | 5 | Specialised agents only if evals show gain | Each hand-off costs money | Phase 5 agents are added only after Phase 4 evals exist |
| D29 | 6 | Shared service layer for dashboard and MCP | One rule set for winning value and "not disclosed" | Requires extracting `queries` |
| D30 | 7 | `refresh_company` is the only model-invokable write, capped | Limits blast radius | Needs cooldown and status response |
| D31 | 8 | Read-only deployments ship a snapshot DB | Free hosts lack persistent disk | Delivery mechanism still open (A28) |
| D32 | 2 (column), 5 (reader) | Per-company status is derived from `run_log` plus a nullable, indexed `run_log.company_id` (built now, backfilled from `stats.company_id`); no `enrichment_state` table | Every planned `enrichment_state` column already exists on the run row; two stores would drift under concurrent writers; the orchestrator and the Phase 7 cooldown both read the latest run | A status query instead of a column; a killed run leaves a stale `running` row the selector must age out |
| D33 | 2 (table), 5 (writer) | News links to companies through `company_news (company_id, news_item_id, news_kind, summary)`, built now since the shape was settled and it is additive; "big news" is `news_kind IS NOT NULL`; no `relevance` score, no `category_rationale`, `website_url` or `fact.verification` column | Many-to-many (an article covers several companies, `news_item.url` is unique); the cut columns have no reader before Phase 6 and are additive if one appears | Built unpopulated: nothing writes it until a Phase 5 matcher (or a later Phase 2 change) exists; the rubric lives in the news prompt, not the schema; a verifier needing more than a second `fact` row and a `confidence` change reopens `fact.verification` |
| D34 | 5 | Pre-screen before enrichment filters to Companies House `accounts.last_accounts.type` of `group` or `full`; `N = min(survivors_after_prescreen, budget_for_this_run / cost_per_company)` over companies needing enrichment only; `budget_for_this_run` is US$0.02 | Project scope is well-established startups (Series B and above), not early discovery; `candidate_score` doesn't predict this (12 of 20 highest-scored Phase 3 candidates enriched to `Other`), but `group`/`full` accounts had 0 false positives across 19 real enriched companies in the pilot sample, every match (Wayve, PolyAI, Synthesia, Graphcore, Cleo, Tractable, Faculty, Peak) is a well-funded, late-stage company | `group`/`full` is a company-size proxy (crossing the UK small-company exemption thresholds), not a direct funding-stage read, and can lag up to a year behind real status; `funding_round` data is the actual Series B+ confirmation once a company is enriched; US$0.02 at ~US$0.015/company is smoke-test scale (≤1 company/run), not the weekly batch figure |
