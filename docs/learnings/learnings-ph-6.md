# Sprout: Learnings - Phase 6 - Multi-agent pipeline at scale

**Planned:** multi-agent orchestration patterns (supervisor/worker, specialisation), model routing for cost, concurrency with `asyncio`, resumable pipelines, verification/cross-checking patterns, failure isolation.

**Actual (done for the classifier, news agent, verifier and orchestrator; the discovery agent is deferred and the per-agent Phase 5 evals have not been run):**

| Topic | Key learning |
| --- | --- |
| Threads over native async | Agents call blocking SQLite, HTTP and ORM code, so concurrency is `asyncio` plus `to_thread` with one resource bundle per worker (own `HttpClient`, fetcher, Companies House client, `Session`). Only the Anthropic client is shared, because it is the only thread-safe one. ORM objects and sessions must never cross threads. |
| Derived status, not a state table | Per-step status is computed from `run_log` (`status.py`), so resume needs no extra table and cannot drift from what actually ran. Restarting the same command skipped 49 of 50 companies and spent nothing. The cost is that a killed process leaves `running` rows, so a reaper (`reap_abandoned`) must turn them into failed attempts at startup. |
| `api_error` is not the company's fault | Failed attempts that count towards the 3-attempt cap exclude `api_error` rows. Otherwise a rate-limit burst would permanently give up healthy companies. |
| A shared budget needs an atomic slice | With four workers, check-then-charge on `BatchBudget` races. `try_slice(cap)` takes `min(cap, remaining)` under a lock and becomes that call's `max_usd`, so overshoot is bounded by one in-flight response per worker. |
| SDK retries before your own | The client is built with `max_retries=5`, so a 429 that reaches the orchestrator has already survived backoff. Only then does the shared `RateLimitGate` pause every worker and re-run the step once. The gate and the 5-trip stop were never triggered live (0 trips), so they are covered by tests only. |
| SQLite under concurrent writers | WAL plus a 30 s busy timeout is enough only because no write transaction is held across an API call: `run_recorded` commits the run row first and writes results afterwards. WAL also means snapshots must use `VACUUM INTO` or the backup API, not a file copy. |
| `DiskCache.put` was not thread-safe | A fixed temp filename collided once workers shared the cache. The temp name now includes pid and thread id. |
| Specialisation is for isolation and routing | A failed classify or news step leaves the profile intact and has its own `run_log` row, cost and failure category; classify and news run on the cheap model, verify on the strong one. Per company the whole pipeline cost about US$0.03 to 0.04 against US$0.077 planned, with enrichment 67% of spend. Quality benefit is unproven until the D28 evals are run, so none of the three added agents is yet shown to help. |
| Independence is enforced in code | The verifier cannot be trusted to judge its own second source. Code accepts `confirmed` or `disagrees` only if the URL was returned by a tool and fetched, is on a different host from the claim's source, and is not among enrichment's own sources. It never changes a value, only confidence and a `verification:<claim>` fact. |
| Mixed tool turns drop work | The verifier once emitted `web_search` calls and `submit_verification` in the same turn. The loop dropped the orphaned searches, so verdicts came out `unverified` without any search being read. Safe, but the check silently did not happen. |
| Pilot before the batch paid off | The 12-company pilot exposed a classifier that invented categories for shells and a news rubric that flagged most items as big. An "answer `Other` unless there is evidence" rule fixed the first, but moved 23 of 50 categories (34 of 50 end `Other`), a possible over-demotion on real startups that only the golden set can show. The rubric change helped only a little (16 of 24 items still big). |
| Pre-screen validation | The `active_officers < 2` pre-screen was too loose rather than too strict: a control run on the five best-scored rejected companies found no real startups, but 5 of the 12 pilot survivors were still shells or unclear. Name-keyword matches all tie at `candidate_score` 4, so ranking falls back to `id`, and thin profiles are largely the pool's property, not the pipeline's. |
| `--limit` is a working set | `--limit N` bounds the set, not the new work, so rerunning completes the same N companies and never reaches further down the pool. This is what makes resume idempotent, and it means a larger run needs a larger `--limit`. |
| Estimate vs actual | The dry run prices verify on every company, so it estimated US$4.05 against US$1.33 actual (verify ran on 3 of 50, only companies with a stage or funding claim). A conservative estimate is safe for a budget gate but misleading as a forecast. |
| Name matching for news | RSS matching by whole-word company name needs legal suffixes stripped and a generic-name guard (`match_name` returns `None`), otherwise single-word names match unrelated stories. Title-token Jaccard dedupe still leaves cross-outlet near-duplicates (3 groups in 24 items), and 9 of 24 items have no published date. |
